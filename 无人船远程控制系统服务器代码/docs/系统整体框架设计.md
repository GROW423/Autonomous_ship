## 一、系统概述

### 1.1 项目目标

开发一套完整的无人船远程投喂控制系统，实现：
- 无人船按设定GPS航路点自动航行撒料，完成后自动返航
- 航行中遇障碍自动避障
- 通过4G网络将船的状态（位置、电池、工作状态、料位、关键部件状态）上传到云平台
- 用户通过微信小程序查看船的状态、遥控船的启停/撒料/返航、在地图上设置航路并上传
- 搭载摄像头，用户可远程查看现场情况
- 支持多用户、多船管理，支持几千条船同时在线

### 1.2 系统三大端

| 端 | 说明 | 技术栈 |
|----|------|--------|
| **船载端** | 安装在无人船上，负责飞控通信、数据采集、4G通信、撒料控制 | OrangePi Zero3 + Python + ArduPilot Rover |
| **云平台** | 部署在服务器上，负责数据存储、指令中转、用户管理、权限控制 | FastAPI + PostgreSQL + Redis + MinIO |
| **小程序端** | 用户使用的微信小程序，负责状态展示、远程控制、路径编辑 | 微信小程序原生开发 / uni-app |

### 3.5 Pixhawk V6 飞控参数配置（ArduPilot Rover）

```
# ===== 机架类型 =====
FRAME_CLASS = 2          # 2=Rover（船/地面车辆）
FRAME_TYPE = 1           # 1=普通船型（差速转向用1，舵机转向用2）

# ===== 解锁与安全 =====
ARMING_CHECK = 1         # 解锁检查（建议开启）
BRD_SAFETYENABLE = 0     # 关闭安全开关（如未接安全开关）

# ===== 航行参数 =====
CRUISE_SPEED = 1.5       # 巡航速度 (m/s)，根据船实际速度调整
WP_SPEED = 1.5           # 航点速度 (m/s)
WP_RADIUS = 2.0          # 航点到达半径 (m)
RTL_SPEED = 2.0          # 返航速度 (m/s)
NAV_ACCEL = 1.0          # 导航加速度 (m/s²)
NAV_TURN_GAIN = 2.0      # 转向增益（根据船转向灵敏度调整）

# ===== 舵机/电调输出 =====
SERVO1_FUNCTION = 73      # 通道1=油门（左推进电机）
SERVO2_FUNCTION = 74      # 通道2=转向/右推进电机（差速转向）
SERVO1_MIN = 1100         # 油门最小值
SERVO1_MAX = 1900         # 油门最大值
SERVO1_TRIM = 1500        # 油门中位（停止）
SERVO2_MIN = 1100
SERVO2_MAX = 1900
SERVO2_TRIM = 1500

# ===== 串口配置（TELEM2接OrangePi） =====
SERIAL2_PROTOCOL = 1      # TELEM2=MAVLink2
SERIAL2_BAUD = 921600     # 波特率921600
SERIAL2_OPTIONS = 0       # 不流控

# ===== GPS配置（和芯星通UM982双天线RTK模块） =====
GPS_TYPE = 1               # GPS类型=Auto（自动检测，支持和芯星通/UBLOX等）
GPS_TYPE2 = 0              # 无第二GPS（UM982双天线通过单接口输出，不需要第二GPS实例）
GPS_DRV_OPTIONS = 0        # 驱动选项（默认）
# UM982特点：双天线RTK，厘米级定位，支持GPS/北斗/GLONASS/Galileo多系统
# 如使用RTK基站差分，可通过MAVLink注入RTCM数据（GPS_INJECT_DATA）

# ===== 返航设置 =====
RTL_ALT = 0                # 返航高度（船用0）
RTL_LOIT_TIME = 0          # 返航后不悬停

# ===== 电池监控 =====
BATT_MONITOR = 4           # 电池监控=电压+电流
BATT_VOLT_PIN = 2          # 电压检测引脚
BATT_CURR_PIN = 3          # 电流检测引脚
BATT_VOLT_MULT = 10.1      # 电压分压比（根据PM02调整）
BATT_AMP_PERVLT = 17.0     # 电流传感器系数

# ===== 避障（如接激光雷达后开启） =====
AVOID_ENABLE = 0           # 先关闭，调试好后开启
AVOID_MARGIN = 2.0         # 避障安全距离 (m)
```

#### 4.1.2 各模块详细说明

| 模块 | 服务名 | 功能 | 输入 | 输出 |
|------|--------|------|------|------|
| 飞控通信 | usv-mavlink | 串口MAVLink通信，解析飞控数据，发送控制指令 | 串口原始数据 | 共享状态（飞控数据） |
| 状态聚合 | usv-aggregator | 数据清洗、字段映射、异常检测、工作模式判断 | 共享状态（原始数据） | 共享状态（聚合后数据） |
| 上报调度 | usv-reporter | 按频率控制上报，gzip压缩，失败重试，本地缓存 | 共享状态（聚合数据） | HTTP POST到云平台 |
| 指令执行 | usv-commander | 轮询云平台指令，解析分发，执行确认 | HTTP GET指令 | 飞控指令/GPIO控制 |
| 图片采集 | usv-camera | USB摄像头拍照，JPEG压缩，按频率上传 | 摄像头图像 | HTTP POST图片到云平台 |
| 撒料控制 | usv-feeder | GPIO/PWM控制撒料电机，软启动，料位联动 | 指令/料位数据 | GPIO输出 |
| 传感器 | usv-sensors | 料位超声波检测，温度检测，4G信号检测，系统状态 | GPIO/系统文件 | 共享状态（传感器数据） |
| 配置管理 | usv-config | 配置文件加载，热更新，远程配置更新 | 配置文件/远程指令 | 各模块配置 |
| 日志监控 | usv-logger | 统一日志，系统状态监控，异常告警 | 各模块日志 | 日志文件/告警 |
| 看门狗 | usv-watchdog | 进程监控，异常重启，网络恢复，磁盘清理 | 各模块心跳 | 系统恢复操作 |

#### boat_bindings（绑定关系表）

CREATE TABLE boat_bindings (

    boat_id INTEGER REFERENCES boats(id) NOT NULL,

## 六、核心业务流程

### 6.1 绑定船流程（小天才模式）

```
用户扫描二维码/输入ICCID+绑定码
    ↓
系统检查船是否存在
    ↓
船不存在 → 报错"未找到该设备"
    ↓
船已存在
    ↓
检查该船是否已有owner
    ↓
无owner（从未被绑定）
    ↓
直接绑定成功，该用户成为owner
设置boats.owner_id = 当前用户
创建boat_bindings(role=owner)
返回：绑定成功，您是该船管理员
    ↓
已有owner
    ↓
检查当前用户是否已绑定
    ↓
已绑定 → 报错"您已绑定该船"
    ↓
未绑定
    ↓
检查船是否允许绑定（bind_enabled=true）
    ↓
不允许 → 报错"该船已关闭绑定功能，请联系管理员"
    ↓
允许
    ↓
创建boat_bind_requests记录(status=pending)
向owner发送小程序订阅消息通知
用户端显示"绑定申请已提交，等待管理员审批"
    ↓
owner在"绑定申请"列表中处理
    ↓
owner点击【同意】
    → 创建boat_bindings(role=viewer)
    → 申请状态=approved
    → 向申请者发送通知"您的绑定申请已通过"
    ↓
owner点击【拒绝】
    → 填写拒绝原因
    → 申请状态=rejected
    → 向申请者发送通知"您的绑定申请被拒绝，原因：XXX"
```

### 6.2 共享者申请控制权限流程

```
viewer在船控制台点击"申请控制"
    ↓
弹出申请页：选择时长 + 填写原因(可选)
时长选项：30分钟 / 1小时 / 2小时 / 4小时 / 自定义
    ↓
创建boat_control_grants记录(status=pending)
向owner发送小程序订阅消息通知
viewer端显示"申请已提交，等待管理员审批"
    ↓
owner在"控制申请"列表中处理
    ↓
owner点击【同意】
    → 可调整时长（默认用申请者申请的时长）
    → 确认后：status=approved, start_time=now, end_time=now+duration
    → 向viewer发送通知"您的控制申请已通过，有效期至XX:XX"
    ↓
owner点击【拒绝】
    → 填写拒绝原因
    → status=rejected
    → 向viewer发送通知"您的控制申请被拒绝"
    ↓
viewer获得限时控制权
控制台显示剩余时间倒计时
控制按钮变为可用
    ↓
授权到期
每次权限校验时检查end_time
已过期 → 自动将status改为expired
控制按钮立即变灰
向viewer发送通知"您的控制权限已到期"
    ↓
owner可随时收回
owner在"已授权"列表中点击【收回控制权】
    → 确认弹窗
    → status=revoked, revoked_at=now
    → 向viewer发送通知"管理员已收回您的控制权限"
```

### 6.3 控制权限校验流程（每次操作前）

```
用户发起控制操作（开始航行/返航/撒料/编辑路径）
    ↓
查询用户在该船的binding角色
    ↓
role=owner → 直接放行
    ↓
role=viewer → 查询是否有有效control_grant
条件：status=approved AND now() BETWEEN start_time AND end_time
    ↓
有有效授权 → 放行，记录剩余时间
    ↓
无有效授权 → 拒绝(403)，提示"您没有控制权限，请先申请"
```

### 6.4 船载端状态上报流程

```
飞控通信模块持续解析MAVLink数据
    → 写入共享状态(/dev/shm/boat_state.json)
    ↓
传感器模块持续采集料位/温度/4G信号
    → 写入共享状态
    ↓
状态聚合模块读取共享状态
    → 数据清洗、字段映射、异常检测
    → 判断工作模式：
      flight_mode=="AUTO" AND armed==true → working
      否则 → idle
    → 更新聚合后的共享状态
    ↓
上报调度模块读取聚合状态
    → 根据work_mode控制频率：
      working → 每1秒上报一次
      idle → 每5秒上报一次
    → gzip压缩数据（500B→150B）
    → HTTP POST到云平台 /api/telemetry/report
    ↓
上报成功 → 记录上报时间，检查是否有缓存数据需要补传
    ↓
上报失败 → 指数退避重试(1s→2s→4s→8s)
    → 重试3次仍失败 → 存入本地SQLite缓存
    → 网络恢复后批量补传缓存数据
```

### 6.5 船载端指令执行流程

```
指令执行模块每2秒轮询云平台
    → GET /api/commands/pull?boat_key=X&last_id=Y
    → 云平台返回大于last_id的所有待执行指令
    ↓
收到指令列表
    → 按指令类型分发：
      飞控控制类 → 飞控通信模块（发MAVLink）
      撒料控制类 → 撒料控制模块（GPIO/PWM）
      图片控制类 → 图片采集模块（切换频率）
      系统控制类 → 系统模块（重启/配置更新）
    ↓
执行指令
    → 高优先级指令（紧急停车）插队立即执行
    → 普通指令按ID顺序执行
    → 记录执行结果：success/failed + 详细结果
    ↓
执行结果写入共享状态
    → 上报调度模块随状态上报到云平台
    → 云平台收到结果后从待执行队列移除
```

### 6.6 图片采集上传流程

```
图片采集模块持续运行
    → 读取共享状态中的viewing标记
    ↓
viewing=true（有人在看）
    → 每1秒拍一张照片
    → 分辨率640×480，JPEG质量70%（约30-50KB）
    ↓
viewing=false（没人看）
    → 每10秒拍一张照片（待机模式可30秒）
    ↓
拍照成功 → HTTP POST到云平台 /api/images/upload
    → multipart/form-data格式，带boat_key/timestamp/viewing标记
    ↓
上传成功 → 云平台存储到MinIO，记录最新图片URL
    ↓
上传失败 → 存入本地图片缓存目录
    → 网络恢复后按时间顺序补传
    → 缓存上限500张，超过删除最旧的
    ↓
4G信号弱时（csq<15）
    → 自动降低分辨率到320×240（约10-20KB）
    → 网络恢复后自动恢复640×480
```

## 八、权限体系

### 8.1 平台级角色

| 角色 | 说明 | 权限范围 |
|------|------|---------|
| 总管理员(admin) | 平台运营方 | 查看所有船、所有用户；强制解绑/转移；管理区域和用户角色 |
| 地方管理员(regional_admin) | 区域负责人 | 查看负责区域内所有船的状态（只读，不可控制） |
| 普通用户(user) | 养殖户/使用者 | 只能看到自己绑定的船 |

### 8.2 船级角色

| 角色 | 说明 | 查看状态 | 控制船 | 管理成员 | 审批申请 |
|------|------|---------|--------|---------|---------|
| 船管理员(owner) | 第一个绑定该船的用户 | ✅ | ✅ 始终 | ✅ | ✅ |
| 共享者(viewer) | 经管理员同意后绑定 | ✅ | ❌ 默认 | ❌ | ❌ |
| 共享者(已授权) | 申请控制权限并获批 | ✅ | ✅ 限时 | ❌ | ❌ |

### 8.3 权限校验规则

1. **查看船状态**：必须是该船的绑定成员（owner或viewer）
2. **控制船**：必须是owner，或有有效的控制授权（status=approved且在有效期内）
3. **管理成员**：必须是owner
4. **审批绑定/控制申请**：必须是owner
5. **转移管理员**：必须是owner，需密码二次确认
6. **创建/删除船**：必须是总管理员
7. **管理区域/用户角色**：必须是总管理员

## 十二、风险与注意事项

### 12.1 硬件风险

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 4G模块供电不足导致重启 | 船载端断连 | 使用带独立供电的USB Hub，降压模块选5A以上 |
| 串口通信不稳定 | 飞控数据丢失 | 确保共地，使用屏蔽线，波特率921600 |
| 摄像头/4G模块USB冲突 | 设备识别失败 | 使用质量好的USB Hub，必要时换用不同USB口 |
| 飞控GPS信号弱 | 定位不准 | GPS天线安装在船顶无遮挡处，远离金属和电调 |
| 防水不到位 | 设备损坏 | 使用IP67防水箱，接头做防水处理，电路板灌胶 |

### 12.2 软件风险

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 4G网络不稳定 | 状态上报中断、指令延迟 | 本地缓存+断点续传，指令轮询机制，网络自动恢复 |
| 飞控串口断开 | 失去航行控制 | 自动重连，看门狗监控，断开超过30秒上报告警 |
| 船载端程序崩溃 | 船失控 | systemd自动重启，看门狗监控，关键操作有超时保护 |
| 云平台服务器故障 | 所有船断连 | 船载端本地缓存，恢复后自动补传，关键任务不中断 |
| 并发量超出预期 | 云平台响应慢 | 架构预留扩展能力，API无状态可水平扩展 |

### 12.3 安全风险

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 未授权用户绑定船 | 数据泄露/非法控制 | 绑定需owner审批，bind_code可重置，可关闭绑定功能 |
| 控制权限滥用 | 船被恶意控制 | 控制限时授权，owner可随时收回，操作日志记录 |
| 船载端被物理破解 | 程序被篡改 | 关键配置加密，远程锁定功能，固件签名验证 |
| 数据传输被窃听 | 位置/数据泄露 | 全链路HTTPS，敏感数据加密传输 |
