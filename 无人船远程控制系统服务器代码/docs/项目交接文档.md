## 一、项目概述

### 1.1 项目目标
开发一套完整的无人船远程投喂控制系统，实现：
- 无人船按设定GPS航路点自动航行撒料，完成后自动返航
- 航行中遇障碍自动避障（可选配激光雷达）
- 通过4G网络将船的状态（位置、电池、工作状态、料位、关键部件状态）上传到云平台
- 用户通过微信小程序查看船的状态、遥控船的启停/撒料/返航、在地图上设置航路并上传
- 搭载摄像头，用户可远程查看现场图片
- 支持多用户、多船管理，支持几千条船同时在线

### 1.2 核心设计决策（已确认，不要轻易修改）

| 决策项 | 选择 | 原因 |
|--------|------|------|
| **通信方式** | 船载端HTTP主动上报 + 指令轮询 | 4G网络不稳定，短连接更可靠；频率低，单机可支撑几千条船 |
| **上报频率** | 待机5s/次，工作1s/次 | 省流量，平衡实时性和流量成本 |
| **指令轮询** | 2s/次 | 船主动拉取指令，不需要长连接 |
| **图片上传** | 没人看10s/张，有人看1s/张 | 按需上传，大幅节省4G流量 |
| **绑定模式** | 小天才手表模式 | 首个绑定者=owner，后续绑定需审批，viewer控制需限时授权 |
| **船身份标识** | 4G物联网卡ICCID | 全球唯一，硬件绑定，比MAVLink系统ID（1-255）更可靠 |
| **前端形态** | 微信小程序 | 用户主要在手机上操作，不需要装APP |
| **飞控固件** | ArduPilot Rover | 成熟的无人船/地面车辆开源固件 |

### 2.4 飞控关键参数（ArduPilot Rover）

```
# ===== 机架类型 =====
FRAME_CLASS = 2          # 2=Rover（船/地面车辆）
FRAME_TYPE = 1           # 1=普通船型（差速转向用1，舵机转向用2）

# ===== 解锁与安全 =====
ARMING_CHECK = 1         # 解锁检查（建议开启）
BRD_SAFETYENABLE = 0     # 关闭安全开关（如未接安全开关）

# ===== 航行参数 =====
CRUISE_SPEED = 1.5       # 巡航速度 (m/s)，根据船实际速度调整
WP_SPEED = 1.5           # 航点速度 (m/s)
WP_RADIUS = 2.0          # 航点到达半径 (m)
RTL_SPEED = 2.0          # 返航速度 (m/s)
NAV_ACCEL = 1.0          # 导航加速度 (m/s²)
NAV_TURN_GAIN = 2.0      # 转向增益（根据船转向灵敏度调整）

# ===== 串口配置（TELEM2接OrangePi） =====
SERIAL2_PROTOCOL = 1      # TELEM2=MAVLink2
SERIAL2_BAUD = 921600     # 波特率921600

# ===== GPS配置（和芯星通UM982双天线RTK模块） =====
GPS_TYPE = 1               # GPS类型=Auto（自动检测）
GPS_TYPE2 = 0              # 无第二GPS

# ===== 电池监控 =====
BATT_MONITOR = 4           # 电池监控=电压+电流
BATT_VOLT_MULT = 10.1      # 电压分压比（根据PM02调整）
BATT_AMP_PERVLT = 17.0     # 电流传感器系数
```

## 三、软件架构

### 3.1 船载端软件（OrangePi Zero3）

运行在 OrangePi Zero3 上，Python 3.9+，共10个模块，由systemd统一管理。

#### 模块总览

| 模块 | 服务名 | 功能 | 输入 | 输出 |
|------|--------|------|------|------|
| 飞控通信 | usv-mavlink | 串口MAVLink通信，解析飞控数据，发送控制指令 | 串口原始数据 | 共享状态（飞控数据） |
| 状态聚合 | usv-aggregator | 数据清洗、字段映射、异常检测、工作模式判断 | 共享状态（原始数据） | 共享状态（聚合后数据） |
| 上报调度 | usv-reporter | 按频率控制上报，gzip压缩，失败重试，本地缓存 | 共享状态（聚合数据） | HTTP POST到云平台 |
| 指令执行 | usv-commander | 轮询云平台指令，解析分发，执行确认 | HTTP GET指令 | 飞控指令/GPIO控制 |
| 图片采集 | usv-camera | USB摄像头拍照，JPEG压缩，按频率上传 | 摄像头图像 | HTTP POST图片到云平台 |
| 撒料控制 | usv-feeder | GPIO/PWM控制撒料电机，软启动，料位联动 | 指令/料位数据 | GPIO输出 |
| 传感器 | usv-sensors | 料位超声波检测，温度检测，4G信号检测，系统状态 | GPIO/系统文件 | 共享状态（传感器数据） |
| 配置管理 | usv-config | 配置文件加载，热更新，远程配置更新 | 配置文件/远程指令 | 各模块配置 |
| 日志监控 | usv-logger | 统一日志，系统状态监控，异常告警 | 各模块日志 | 日志文件/告警 |
| 看门狗 | usv-watchdog | 进程监控，异常重启，网络恢复，磁盘清理 | 各模块心跳 | 系统恢复操作 |

### 3.3 小程序端软件架构

#### 页面结构（8个页面）

1. **登录注册页**
   - 用户名密码登录
   - 新用户注册

2. **船列表页（首页）**
   - 搜索框（船名/ICCID模糊搜索）
   - 区域筛选
   - 船卡片列表：名称、在线状态、电量、角色标签
   - [+ 绑定新船]按钮

3. **船控制台页**
   - 顶部：船名、在线状态、角色标签、剩余控制时间
   - 地图：船实时位置、设定航线（蓝色虚线）、实际轨迹（绿色）
   - 状态面板：位置、电池、速度、航向、饲料、4G信号、箱温
   - 图片监控：最新图片（1s刷新）/ 历史图片
   - 控制栏：开始航行/返航/紧急停车/开投料/关投料/编辑路径
   - [成员管理]入口（仅owner可见）

4. **绑定新船页**
   - 扫描二维码 / 手动输入ICCID+绑定码
   - 提交后显示"等待管理员审批"状态

5. **成员管理页（仅owner）**
   - Tab：待审批绑定 / 成员列表 / 控制申请 / 已授权 / 历史
   - 待审批绑定：同意/拒绝
   - 成员列表：解除绑定/转移管理员
   - 控制申请：同意（可调整时长）/拒绝
   - 已授权：收回控制权

6. **申请控制弹窗**
   - 选择时长（30分/1小时/2小时/4小时/自定义）
   - 填写申请原因（可选）

7. **路径编辑页**
   - 地图上点击添加航点
   - 拖动航点调整位置
   - 右键删除航点

## 五、核心业务流程

### 5.1 绑定船流程（小天才模式）

1. 用户扫描二维码/输入ICCID+绑定码
2. 系统检查船是否存在 → 不存在报错
3. 检查该船是否已有owner：
   - **无owner（从未被绑定）** → 直接绑定成功，该用户成为owner，创建boat_bindings(role=owner)
   - **已有owner** → 检查当前用户是否已绑定 → 未绑定则创建boat_bind_requests记录(status=pending)，向owner发送通知
4. owner在"绑定申请"列表中处理：
   - 同意 → 创建boat_bindings(role=viewer)，申请状态=approved
   - 拒绝 → 填写拒绝原因，申请状态=rejected

### 5.2 共享者申请控制权限流程

1. viewer在船控制台点击"申请控制"
2. 弹出申请页：选择时长 + 填写原因(可选)
3. 创建boat_control_grants记录(status=pending)，向owner发送通知
4. owner在"控制申请"列表中处理：
   - 同意 → 可调整时长，确认后status=approved, start_time=now, end_time=now+duration
   - 拒绝 → 填写拒绝原因，status=rejected
5. viewer获得限时控制权，控制台显示剩余时间倒计时
6. 授权到期 → 自动将status改为expired，控制按钮立即变灰
7. owner可随时收回 → status=revoked, revoked_at=now

### 5.3 船载端状态上报流程

1. 飞控通信模块持续解析MAVLink数据 → 写入共享状态
2. 传感器模块持续采集料位/温度/4G信号 → 写入共享状态
3. 状态聚合模块读取共享状态 → 数据清洗、字段映射、异常检测
4. 判断工作模式：
   - flight_mode=="AUTO" AND armed==true → working
   - 否则 → idle
5. 上报调度模块读取聚合状态：
   - working → 每1秒上报一次
   - idle → 每5秒上报一次
6. gzip压缩数据（500B→150B）→ HTTP POST到云平台 /api/telemetry/report
7. 上报成功 → 记录上报时间，检查是否有缓存数据需要补传
8. 上报失败 → 指数退避重试(1s→2s→4s→8s)，重试3次仍失败 → 存入本地SQLite缓存

### 5.4 船载端指令执行流程

1. 指令执行模块每2秒轮询云平台 → GET /api/commands/pull
2. 收到指令列表 → 按指令类型分发：
   - 飞控控制类 → 飞控通信模块（发MAVLink）
   - 撒料控制类 → 撒料控制模块（GPIO/PWM）
   - 图片控制类 → 图片采集模块（切换频率）
   - 系统控制类 → 系统模块（重启/配置更新）
3. 执行指令 → 记录执行结果：success/failed + 详细结果
4. 执行结果写入共享状态 → 上报调度模块随状态上报到云平台

### 5.5 图片采集上传流程

1. 图片采集模块持续运行 → 读取共享状态中的viewing标记
2. viewing=true（有人在看）→ 每1秒拍一张照片，分辨率640×480，JPEG质量70%（约30-50KB）
3. viewing=false（没人看）→ 每10秒拍一张照片
4. 拍照成功 → HTTP POST到云平台 /api/images/upload
5. 上传失败 → 存入本地图片缓存目录，网络恢复后按时间顺序补传
6. 4G信号弱时（csq<15）→ 自动降低分辨率到320×240

## 六、权限体系

### 6.1 平台级角色

| 角色 | 说明 | 权限范围 |
|------|------|---------|
| 总管理员(admin) | 平台运营方 | 查看所有船、所有用户；强制解绑/转移；管理区域和用户角色 |
| 地方管理员(regional_admin) | 区域负责人 | 查看负责区域内所有船的状态（只读，不可控制） |
| 普通用户(user) | 养殖户/使用者 | 只能看到自己绑定的船 |

### 6.2 船级角色

| 角色 | 说明 | 查看状态 | 控制船 | 管理成员 | 审批申请 |
|------|------|---------|--------|---------|---------|
| 船管理员(owner) | 第一个绑定该船的用户 | ✅ | ✅ 始终 | ✅ | ✅ |
| 共享者(viewer) | 经管理员同意后绑定 | ✅ | ❌ 默认 | ❌ | ❌ |
| 共享者(已授权) | 申请控制权限并获批 | ✅ | ✅ 限时 | ❌ | ❌ |

### 6.3 权限校验规则

1. **查看船状态**：必须是该船的绑定成员（owner或viewer）
2. **控制船**：必须是owner，或有有效的控制授权（status=approved且在有效期内）
3. **管理成员**：必须是owner
4. **审批绑定/控制申请**：必须是owner
5. **转移管理员**：必须是owner，需密码二次确认
6. **创建/删除船**：必须是总管理员
7. **管理区域/用户角色**：必须是总管理员

## 九、关键技术细节与注意事项

### 9.1 已验证的死路（不要重复尝试）

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| pymavlink 2.4.49的`mavlink_connection(socket_obj)`不可用 | 版本兼容性问题，报startswith错误 | 新架构改用HTTP主动上报，不需要这个功能 |
| 香橙派apt-get upgrade失败 | dpkg statoverride无效组引用 + 安装大量桌面包耗时过长 | 跳过upgrade，只安装必要的包 |
| 电脑Python 3.13安装pymavlink失败 | 编译问题 | 在香橙派上用Python 3.9，不要在Windows上装pymavlink |
| go2rtc v1.9.8从GitHub下载在香橙派上超时失败 | 网络问题 | 新架构改用图片轮询，不需要go2rtc |
| ICCID字段要求min_length=15，TESTICCID001（12位）不符合 | 字段约束 | 测试时用15位以上的ICCID，如898600TEST000000001 |

### 9.2 硬件接线注意事项

1. **共地必须做好**：所有设备（飞控、Zero3、电调、传感器）必须共地，否则会有通信干扰
2. **串口电平匹配**：Pixhawk TELEM2是3.3V TTL，OrangePi串口也是3.3V，可直接连接，但TX/RX要交叉连接（橙派TX→飞控RX，橙派RX→飞控TX）
3. **USB Hub必须带独立供电**：4G模块和摄像头同时工作电流较大，无源USB Hub会导致供电不足重启
4. **GPS天线安装**：UM982双天线需安装在船顶无遮挡处，两根天线沿船首尾方向安装，间距建议≥0.5m，用于测量航向
5. **防水**：所有电子设备放在IP67防水箱内，接头做防水处理，电路板建议灌胶或涂三防漆

### 9.3 软件注意事项

1. **飞控参数必须实船调试**：导航PID参数、巡航速度、航点半径等需要根据实际船体调整，不能直接用默认值
2. **Redis存储布尔值**：hset不支持bool类型，需要转为int（0/1）存储，读取时再转回bool
3. **Windows CRLF换行符问题**：在Windows上编辑的shell脚本/配置文件，复制到Linux上会因为CRLF换行符导致执行失败，需要用dos2unix转换
4. **systemd服务管理**：船载端所有服务用systemd管理，确保开机自启、崩溃自动重启
5. **gzip压缩**：状态上报前用gzip压缩，可减少约70%的数据量，节省4G流量
6. **本地缓存补传**：网络断开时，上报数据存入本地SQLite缓存，网络恢复后批量补传，确保数据不丢失

### 9.4 业务注意事项

1. **首个绑定者=owner**：船添加到系统后，第一个绑定的用户自动成为owner，后续绑定需审批，确保船的归属清晰
2. **控制授权到期自动失效**：viewer的控制权限到期后自动失效，不需要手动收回，避免权限泄漏
3. **同一时间只有一个控制者**：同一艘船，owner和viewer不能同时控制，viewer有有效授权时owner的控制权不冲突（owner始终有控制权）
4. **航路点保存为任务**：航线不需要每次重新上传，保存为任务后可反复调用，每个船可存多条航线
5. **区域分类**：船按区域分类（如广州南沙、珠海、台山），地方管理员只能看到自己负责区域的船

## 十二、下一步开发建议

### 优先级排序

1. **最高优先级**：完成云平台船载端接口（状态上报、指令队列、图片上传），跑通"船载端→云端→小程序"的数据流
2. **高优先级**：开发船载端核心模块（飞控通信、状态上报、指令执行），用模拟数据跑通
3. **中优先级**：开发微信小程序核心页面（登录、船列表、控制台）
4. **低优先级**：Web前端优化、用户体验打磨

### 建议的开发顺序

```
1. 云平台船载端接口完成 + 数据库迁移执行
   ↓
2. 船载端模拟程序（Python脚本，模拟MAVLink数据上报）
   ↓
3. 云平台+模拟船联调（小程序能看到模拟船的状态）
   ↓
4. 船载端真实硬件联调（Pixhawk + OrangePi）
   ↓
5. 小程序开发（可以和船载端并行开发）
   ↓
6. 整体联调 + 测试
   ↓
7. 现场部署
```
